# Models & Data: SQLAlchemy, pyramid_tm, requests

The SQLAlchemy starter integrates SQLAlchemy with **pyramid_tm** (a per-request
transaction manager) and **zope.sqlalchemy**, exposing the ORM session as
`request.dbsession`. This is the standard, battle-tested pattern.

## The moving parts

- **`pyramid_tm`** — opens a transaction at the start of each request and
  commits it if the request succeeds (status < 400) or aborts it on an
  exception / 4xx-5xx. You almost never call `commit()`/`rollback()` yourself.
- **`zope.sqlalchemy`** (`register(session)`) — joins the SQLAlchemy session to
  that transaction so ORM writes are committed/rolled back together.
- **`request.dbsession`** — a request-scoped session added via
  `add_request_method(..., reify=True)`. Created lazily, closed at request end.

## models/__init__.py (wiring)

```python
from sqlalchemy import engine_from_config
from sqlalchemy.orm import sessionmaker, configure_mappers
import zope.sqlalchemy

from .meta import Base
from .mymodel import MyModel          # noqa: F401  (import so mappers configure)

configure_mappers()


def get_engine(settings, prefix="sqlalchemy."):
    return engine_from_config(settings, prefix)


def get_session_factory(engine):
    factory = sessionmaker()
    factory.configure(bind=engine)
    return factory


def get_tm_session(session_factory, transaction_manager, request=None):
    dbsession = session_factory(info={"request": request})
    zope.sqlalchemy.register(dbsession, transaction_manager=transaction_manager)
    return dbsession


def includeme(config):
    settings = config.get_settings()
    settings["tm.manager_hook"] = "pyramid_tm.explicit_manager"   # explicit tm mode

    config.include("pyramid_tm")
    config.include("pyramid_retry")           # retry on transient/conflict errors

    session_factory = get_session_factory(get_engine(settings))
    config.registry["dbsession_factory"] = session_factory

    config.add_request_method(
        lambda request: get_tm_session(
            session_factory, request.tm, request
        ),
        "dbsession",
        reify=True,
    )
```

## meta.py + a model

```python
# meta.py
from sqlalchemy.orm import declarative_base
from sqlalchemy.schema import MetaData

NAMING_CONVENTION = {
    "ix": "ix_%(column_0_label)s",
    "uq": "uq_%(table_name)s_%(column_0_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}
metadata = MetaData(naming_convention=NAMING_CONVENTION)
Base = declarative_base(metadata=metadata)
```

# mymodel.py
from sqlalchemy import Column, Index, Integer, Text
from .meta import Base


class MyModel(Base):
    __tablename__ = "models"
    id = Column(Integer, primary_key=True)
    name = Column(Text)
    value = Column(Integer)


Index("my_index", MyModel.name, unique=True, mysql_length=255)

## Using it in a view

> For anything beyond a trivial lookup — joins, filtering, eager loading to avoid
> N+1, pagination, aggregates, bulk writes — see the dedicated deep-dive in
> **`references/querying-sqlalchemy.md`**. Prefer the SQLAlchemy **2.0 `select()`
> style** shown there over the legacy `session.query(...)` API.

```python
from pyramid.view import view_config
from pyramid.httpexceptions import HTTPNotFound
from sqlalchemy import select
from ..models import MyModel


@view_config(route_name="thing", renderer="json")
def thing(request):
    # 2.0 style; session.get(MyModel, id) is even better for a PK lookup.
    obj = request.dbsession.scalars(
        select(MyModel).where(MyModel.id == request.matchdict["id"])
    ).one_or_none()
    if obj is None:
        raise HTTPNotFound()
    return {"name": obj.name, "value": obj.value}


@view_config(route_name="thing_add", request_method="POST")
def add(request):
    request.dbsession.add(MyModel(name=request.POST["name"], value=1))
    # no commit — pyramid_tm commits when the request succeeds
    return HTTPFound(request.route_url("home"))
```

To force a failed transaction, raise an exception or return a 4xx/5xx — pyramid_tm
aborts it. Use `transaction.abort()` explicitly only when you must roll back but
still return success.

## Reading rows early

`request.dbsession.flush()` sends pending SQL (e.g. to get an autogenerated `id`)
without committing. Avoid manual `commit()`; it fights pyramid_tm.

## Migrations with Alembic

The starter includes an `alembic/` env bound to the app settings.

```bash
alembic -c development.ini revision --autogenerate -m "add users table"
alembic -c development.ini upgrade head
alembic -c development.ini downgrade -1
```

`--autogenerate` diffs `Base.metadata` against the DB — always review the
generated migration, especially for type changes and server defaults.

## initialize_db / console scripts

Management commands load the app environment via `pyramid.paster.bootstrap` or
`get_appsettings`:

```python
import sys
from pyramid.paster import bootstrap, setup_logging
from pyramid.scripts.common import parse_vars
from ..models import MyModel


def main(argv=sys.argv):
    config_uri = argv[1]                       # e.g. development.ini
    setup_logging(config_uri)
    options = parse_vars(argv[2:])
    with bootstrap(config_uri, options=options) as env:
        with env["request"].tm:                # a transaction
            dbsession = env["request"].dbsession
            dbsession.add(MyModel(name="one", value=1))
```

Register it under `[console_scripts]` (setup.py/pyproject.toml) so
`initialize_db development.ini` works.

## Notes / gotchas

- Enable `pyramid_retry` so requests that fail with a transient DB conflict
  (`TransientError`) are retried automatically — pairs with explicit tm mode.
- Log SQL in dev by setting the `sqlalchemy.engine` logger to `INFO`/`DEBUG`
  in the `.ini` logging section.
- Other backends: **ZODB** (object DB via `pyramid_zodbconn`, traversal-friendly)
  and any non-ORM store — the same `add_request_method` + `pyramid_tm` pattern
  applies if the store integrates with the `transaction` package.
